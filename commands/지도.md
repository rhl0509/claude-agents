graphify 스킬로 이 프로젝트의 코드 지도를 다뤄줘.

입력: $ARGUMENTS

지도는 `graphify-out/graph.json` 하나다 — 노드(함수·클래스·모듈)와 링크(calls·imports)의 목록이고, `graph.html`·`GRAPH_REPORT.md`는 그걸 사람이 보기 좋게 바꾼 것뿐이다.

## 무엇을 할지 판단

1. **입력이 코드베이스에 대한 질문이고 `graphify-out/graph.json`이 있으면** → 지도부터 조회한다. 파일을 넓게 읽지 마라. `graphify query "<질문>"`, 두 대상 사이 경로는 `graphify path "A" "B"`, 한 노드 설명은 `graphify explain "X"`, 무엇이 X를 부르는지는 `graphify affected "X" --relation calls`. 필요하면 `graph.json`을 직접 파싱해도 된다(최상위 키는 `nodes`와 **`links`** — `edges`가 아니다).
2. **입력이 비었고 지도가 없으면** → 현재 디렉터리에 새로 만든다.
3. **입력이 비었고 지도가 있으면** → 코드 변경분을 반영해 갱신한다.
4. **입력이 경로면** → 그 경로로 만든다.

## 만들 때

- 기본은 `graphify extract <경로> --code-only`. AST만 쓰므로 **LLM 토큰 0, API 키 불필요, 서브에이전트 불필요**다. 문서·이미지를 넣으면 semantic 추출이 돌아 토큰을 쓰니, 넣을지 먼저 사용자에게 묻는다.
- 이어서 `graphify cluster-only <경로> --graph <경로>/graphify-out/graph.json --no-label`로 리포트·HTML을 만든다.
- **단일 프로젝트에 `merge-graphs`를 쓰지 마라.** 하위 폴더별로 뽑아 병합하면 노드에 `repo` 태그가 박혀, 이후 갱신이 `ValueError: nodes span multiple repos`로 죽는다. 루트에서 한 번에 뽑는다. 이미 그 상태면 `--force`로 전체 재추출해야 풀린다.
- `.gitignore`는 자동 존중되므로 `.venv`·`node_modules`는 알아서 빠진다. 프로젝트 `.gitignore`에 `graphify-out/`이 없으면 추가를 제안한다.

## 커뮤니티 라벨 (한국어)

클러스터는 기본적으로 `Community 0`, `Community 1` … 로 남는다. 그대로 두지 말고 **구성원 파일·심볼을 보고 한국어 이름을 붙인다**(예: `인증·세션`, `API: 총계정원장·전표`, `화면: 재무제표`, `마이그레이션: 부가세`, `테스트: 기간 마감`). 붙이는 법:

1. 커뮤니티별 구성원과 대표 파일을 뽑는다.
2. 이름을 정해 `graphify-out/.graphify_labels.json`에 `{"0": "이름", ...}`로 저장한다.
3. `graph.json`의 각 노드 `community_name`에 그 이름을 넣는다.
4. `graphify export html`로 HTML만 다시 만든다.
5. `GRAPH_REPORT.md`의 `Community N` 문자열도 같은 이름으로 치환한다.

⚠️ **`cluster-only`나 `update`를 다시 돌리면 커뮤니티 번호가 재배정돼 라벨이 날아간다.** 갱신 후에는 `.graphify_labels.json`이 여전히 맞는지 확인하고, 어긋났으면 다시 붙인다. 라벨을 지키려면 재클러스터링 없이 `graphify export html`만 돌린다.

## 보고

무엇을 만들었는지가 아니라 **무엇을 알게 됐는지**를 보고한다. God Nodes(연결이 몰린 허브)와 커뮤니티 구성은 표로, 지도가 답할 수 있는 가장 쓸모 있는 질문 하나를 제안한다. 지도에서 빠진 것(파서가 스킵한 확장자·`--code-only`로 제외한 문서·고립 노드 수)은 숨기지 말고 함께 밝힌다.
