`reference_jasoseo_workflow` 메모리의 표준 절차대로, 채용 공고에 맞춰 자기소개서를 **메인 세션에서 직접** 작성한다(읽기 전용 서브에이전트로 넘기지 말 것 — 서식 다운로드·파일 저장이 필요하므로).

대상(공고 URL/텍스트·업체명): $ARGUMENTS

절차:
1. 공고(JD)에서 지원 직무·요구 역량·키워드·인재상 추출(URL이면 WebFetch).
2. 채용 첨부 서식(자기소개서 hwpx)이 있으면 다운로드해 **실제 문항·유의사항(글자수/분량/폰트)** 확인 — 공고 본문 문항과 다를 수 있으니 서식 문항을 우선한다.
3. 지원자 이력서/경력(기본 `E:\이력서\`)의 **실제 팩트만** 각 문항에 매핑(강/중/공백). 없는 경력·수상·수치·자격 창작 금지 — 근거 없는 요구는 "공백"으로 표시하고 사용자에게 되묻는다.
4. 서식 문항·글자수에 맞춰 재작성(두괄식·STAR·직무 연결, 한 사례를 두 문항에 중복 사용 금지).
5. `E:\이력서\[업체명]\` 폴더에 결과물 저장: `.txt`(복붙용) + `.docx`(서식 형식 13pt·한컴바탕·160%). 원본 이력서·서식 원본은 수정하지 않는다.

작업 시작 전 `reference_jasoseo_workflow`(툴체인: olefile로 hwp 읽기·zip/OWPML로 hwpx 읽기·python-docx로 docx·fileDownload.do 첨부 다운로드)와 이력서 관련 메모리를 회상해 반영한다. 순수 텍스트 초안만 빠르게 필요하면 `cover-letter-tailor` 서브에이전트를 쓸 수 있으나, 파일 저장·다운로드는 메인 세션이 한다.
