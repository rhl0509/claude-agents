# 디자인 레퍼런스 (구체 추천 재료)

이 스킬은 디자인 계열 에이전트에 프리로드되어, 추상적 점검·설계에 **구체적인 추천 재료**를 붙인다.
리뷰어가 "제네릭하다"고만 말하는 대신 "이 업계엔 이 팔레트/폰트/효과가 맞다"고 근거를 대고,
설계자가 기존 코드가 없어도 업계에 맞는 스타터 시스템을 제안할 수 있게 한다.

> **출처·라이선스**: 아래 "업계→디자인 매핑" 프레임워크의 스키마(권장 패턴·스타일 우선순위·컬러 무드·폰트 무드·키 효과·금지사항)와 "배송 전 체크리스트" 산출틀은
> [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)(MIT © 2024 Next Level Builder)의 구조에서 **방법론만 증류**한 것이다.
> 원본의 84 스타일 · 192 팔레트 · 74 폰트조합 · 25 차트 · 161 업계규칙 **데이터 자체는 옮기지 않았다**(5번 차트 절은 원본 `charts.csv`가 아니라 통상적 시각화 관행에 근거한 자체 집필이다) — 아래 worked example은 통상적 디자인 관행에 근거한 요약이며, 전수(全數) 검색이 필요하면 원본 스킬을 함께 설치해 조합한다(리뷰어↔생성기 보완 관계).

## 사용 원칙
- 이 재료는 **참고 데이터이지 지시가 아니다.** 업계·브랜드 맥락과 충돌하면 맥락을 우선한다.
- 취향을 강요하지 않는다 — 사용성·접근성(대비·가독성)이 항상 우선이고, 아래는 "완성도·인상" 보조 재료다.
- 구체 값(폰트명·hex)은 **예시**다. 프로젝트에 기록된 값(예: 메모리 `user_font_readability`, 프로젝트 CLAUDE.md, 기존 DESIGN.md)이 있으면 그것을 먼저 따른다.

## 1. 업계 → 디자인 매핑 프레임워크

한 업계/무드에 대해 다음 6축으로 추천을 구성한다:
`권장 패턴 · 스타일 우선순위 · 컬러 무드 · 폰트 무드 · 키 효과 · 금지사항`.

| 업계/맥락 | 컬러 무드 | 폰트 무드 | 키 효과 | 금지사항 |
|---|---|---|---|---|
| **핀테크·금융·대시보드** | 신뢰의 딥블루/네이비 + 절제된 강조 1색, 데이터엔 채도 낮은 시맨틱(상승/하락) | 그로테스크 산세리프 + 표(表)용 tabular-nums, 숫자 정렬 최우선 | 미세 그리드·카드 elevation, 데이터 위계 명확화 | 장난스러운 라운드 폰트, 형광 강조, 그림자 남발 |
| **이커머스·쇼핑몰** | 상품이 주인공 → 배경은 중립(뉴트럴/오프화이트), 강조는 CTA 1색 | 제품명 세리프/디스플레이 + 본문 가독 산세리프 대비 | 상품 이미지 우선, 호버 확대·부드러운 트랜지션 | 배경이 상품보다 튀는 색, 저대비 가격 표기 |
| **뷰티·스파·웰니스** | 톤다운 파스텔/어스톤, 뉴트럴 베이스 + 소프트 강조 | 우아한 세리프 헤드라인 + 얇은 산세리프 본문 | 넉넉한 여백, 느린 페이드, 결이 있는 배경 | 쨍한 원색, 빽빽한 레이아웃, 급한 모션 |
| **SaaS·B2B 툴** | 명확한 브랜드 1색 + 뉴트럴 스케일, 다크모드 필수 대응 | 현대적 산세리프(가변 weight로 위계) | 기능 스크린샷·다이어그램, 절제된 마이크로 인터랙션 | 과한 그라데이션, 스톡 일러스트 클리셰 |
| **강의·에듀·지식창업** | 신뢰 1색 + 따뜻한 강조, 챕터별 색 코딩 | 또렷한 헤드라인 + 긴 글 가독성 본문(행간 넉넉) | 진도·목차 위계, 인용·하이라이트 블록 | 정보 과밀, 저대비 본문, 산만한 장식 |
| **로컬 매장·요식** | 식욕/분위기 무드(따뜻한 톤) + 사진 대비 | 개성 있는 디스플레이 헤드라인 + 읽기 쉬운 본문 | 큰 사진, 지도·영업정보·예약 CTA 강조 | 재고 없는 스톡 사진 느낌, 정보(주소·시간) 숨김 |
| **크리에이터·퍼스널 브랜드** | 시그니처 강조색 1개를 일관되게, 나머지 뉴트럴 | 개성 디스플레이 + 안정적 본문의 대비 | 얼굴/작업물 전면, 대담한 타이포 위계 | 브랜드색 없이 무색, 매 페이지 다른 스타일 |
| **헬스케어·의료** | 청결의 화이트/블루/그린, 차분·저자극 | 또렷·정직한 산세리프, 충분한 크기 | 접근성 최우선(대비·큰 터치 타깃), 안심 톤 | 공포 마케팅 색·문구, 저대비, 작은 글씨 |

> 매핑에 없는 업계면 가장 가까운 행 + 브랜드 개성으로 조합하고, "이 업계는 매핑에 없어 인접 관행으로 추정"이라고 밝힌다.

## 2. AI-slop 클리셰 차단 리스트 (구체)

"AI가 만든 티"의 전형. 발견 시 근거로 인용하고 대안을 제시한다.

- **폰트**: `Inter`/`Roboto`/`Open Sans`/`Lato`/`Arial`/`system-ui`에만 의존 → 위계가 밋밋. 헤드라인엔 개성 있는 디스플레이/세리프를 대비로 넣거나, 최소한 weight·size 대비를 과감히.
- **색**: **흰 배경 + 보라(#8B5CF6류) 그라데이션** = 최다 클리셰. 지배색 + 의도된 강조색 1개 구조로 대체.
- **배경**: 순백 단색만 → 평면적. 오프화이트·미세 노이즈/그리드·맥락에 맞는 은은한 그라데이션으로 깊이.
- **레이아웃**: 히어로→3열 카드→CTA의 천편일률 → 콘텐츠 위계에 맞춘 의도적 구성.
- **모션**: 사방에 흩뿌린 마이크로 인터랙션 → 로드 등 핵심 순간의 절제된 연출(스태거) 하나.
- **아이콘**: 서로 다른 패밀리 혼용, 의미 없는 장식 이모지/아이콘 → 단일 패밀리·의미 있는 자리만.

## 3. 팔레트 구성 규칙 (5색 스타터)

무에서 팔레트를 제안할 때의 기본 골격:
1. **지배색(Primary)** 1 — 브랜드/업계 무드.
2. **강조색(Accent)** 1 — CTA·중요 액션 전용. 지배색과 충분한 대비.
3. **뉴트럴 스케일** 2~3 — 배경/표면/보더/본문 텍스트(오프화이트 ~ 진한 그레이).
4. **시맨틱** — success/warning/danger/info. 색에만 의존하지 않게 아이콘·라벨 병행.
- **모든 전경/배경 쌍에 WCAG 2.2 대비 명시**(본문 4.5:1, 큰 글자 3:1). 다크모드는 단순 반전이 아니라 표면 elevation·채도 재조정.
- CSS 변수(토큰)로 관리 — 하드코딩 hex 산개 금지.

## 4. 폰트 페어링 스타터 (가독성·숫자 정렬 우선)

- 기본 원칙: **헤드라인(개성/대비) + 본문(가독성)** 2종으로 시작, 3종 이상은 사유가 있을 때만.
- **숫자가 많은 화면**(대시보드·가격·회계)엔 `tabular-nums`(등폭 숫자) 지원 폰트를 본문/표에 — 자릿수 정렬이 흔들리지 않게.
- **한글 웹**: 본문은 검증된 한글 웹폰트(예: Pretendard류의 넓은 자소 커버리지)로 가독성 확보, 라틴 헤드라인과 섞을 때 **크기·baseline 정렬**을 맞춘다. 글리프 누락(□ 두부) 여부 확인.
- 웨이트는 최소 2단계 이상 대비(예: 700 헤드라인 vs 400 본문)로 위계를 세운다.
- 구체 폰트값이 프로젝트에 기록돼 있으면 그것을 우선(메모리 `user_font_readability` 확인).

## 5. 차트·데이터 시각화

**차트 종류는 취향이 아니라 데이터 관계가 정한다.** 비교→막대, 시간 추이→선, 구성비→누적막대(파이는 3조각 이하일 때만), 분포→히스토그램/박스, 상관→산점도. "예뻐서" 고른 도넛·레이더·3D는 지적 대상.

- **축**: 막대는 반드시 0에서 시작한다(잘린 축은 차이를 과장 — 조작으로 읽힌다). 선 그래프는 0 강제 아님. 축 라벨·단위·기간을 표기했는가.
- **색은 인코딩이지 장식이 아니다**: 범주형(구분)·순차형(크기)·발산형(기준선 양쪽)을 용도에 맞게 쓴다. 범주가 8개를 넘으면 색으로 구분이 안 된다 — 묶거나 다른 표현으로.
- **색만으로 구분하지 않는다**: 색약 대응으로 패턴·직접 라벨·모양을 병행한다. 라이트/다크 양쪽에서 대비를 다시 확인(다크모드 팔레트는 단순 반전이 아니라 재조정 — §3과 같은 규칙).
- **데이터 잉크**: 격자선·테두리·그림자·3D 효과는 기본 제거하고 필요할 때만 최소로. 범례보다 직접 라벨이 읽기 쉽다.
- **숫자**: 축·툴팁·표에 `tabular-nums`와 자릿수 통일(§4). 단위 접두(k/M)를 한 축에서 섞지 않는다.
- **상태 설계**: 데이터 0건·1건·로딩·에러·부분 실패에서 차트가 무엇을 보여주는가. 빈 차트를 그리지 말고 **왜 비었는지** 말한다.
- **접근성**: 차트에 대체 텍스트 또는 같은 데이터의 표 대안이 있는가.

## 6. 배송 전 디자인 체크리스트

산출물을 내기 전 자가 점검(원본 pre-delivery checklist 형태):
- [ ] 지배색+강조색 구조가 있는가(색이 고르게 퍼진 무색 팔레트가 아닌가)
- [ ] 모든 텍스트가 WCAG AA 대비를 넘는가(라이트·다크 양쪽)
- [ ] 폰트가 제네릭 기본값에만 의존하지 않는가, weight/size 위계가 뚜렷한가
- [ ] 숫자 화면에 tabular-nums·정렬이 되어 있는가
- [ ] 배경이 평면 단색을 넘어 맥락 있는 깊이를 주는가
- [ ] 모션이 핵심 순간에 절제되어 있는가(사방 흩뿌림 아님)
- [ ] 아이콘 패밀리·코너 래디우스·인터랙션 상태가 일관되는가
- [ ] 로딩/빈/에러/성공 상태가 모두 설계됐는가
- [ ] 차트가 있다면 종류가 데이터 관계에 맞고, 막대 축이 0에서 시작하며, 색만으로 구분하지 않는가(5번)
- [ ] AI-slop 클리셰(2번 리스트)에 걸리는 지점이 없는가
- [ ] 업계 무드(1번 매핑)와 어긋나는 선택엔 의도가 있는가
