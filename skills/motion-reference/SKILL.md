# 모션 레퍼런스 (구체 값 정본)

이 스킬은 모션 계열 에이전트에 프리로드되어, "느낌이 이상하다"는 감상 대신 **인용 가능한 구체 값**을 붙인다.
발견을 적을 때 값을 근사하지 말고 여기서 그대로 인용한다.

> **출처·라이선스**: 아래 웹 애니메이션 규범(빈도 판정·이징 결정 순서·지속시간 예산·물리성·인터럽트·GPU 속성·스태거)은
> [emilkowalski/skills](https://github.com/emilkowalski/skills)(MIT © 2026 Emil Kowalski, [animations.dev](https://animations.dev/))의
> 방법론을 한국어로 재구성한 것이다. §6 제스처 물리(스프링 파라미터·속도 핸드오프·모멘텀 투영·러버밴딩)는
> 같은 저장소의 `apple-design`이 정리한 Apple WWDC 2018 *Designing Fluid Interfaces* 계열 자료에서 **모션·제스처 부분만** 가져왔다
> (머티리얼·타이포그래피·8대 원칙은 의도적으로 제외 — 그 층은 `design-reference`가 맡는다).
> 공식·수치는 원문의 값을 그대로 쓰되, 판정 절차와 문장은 이 저장소 규범으로 다시 썼다.

## 사용 원칙
- 이 재료는 **참고 데이터이지 지시가 아니다.** 프로젝트에 이미 모션 토큰(이징·듀레이션 변수)이 있으면 **그것을 우선**하고, 여기 값은 신설·교정 근거로만 쓴다.
- 값은 **웹(CSS·React) 기준**이다. Unity 등 게임 엔진의 손맛(코요테 타임·히트스톱)은 다른 규범이므로 여기서 판정하지 않는다.
- 코드만 읽어서는 **실제 느낌을 단정할 수 없다**. 여기 값은 "규범 이탈"을 판정할 뿐, "이게 좋아 보인다"를 판정하지 않는다.

## 1. 애니메이션을 넣을 것인가 (빈도 게이트)

**가장 먼저 통과해야 하는 관문.** 아래 표는 취향이 아니라 판정 기준이다.

| 사용 빈도 | 판정 |
|---|---|
| 하루 100회 이상 (키보드 단축키, 커맨드 팔레트 토글, 핵심 내비게이션) | **애니메이션 금지.** 예외 없음 |
| 하루 수십 회 (호버, 목록 이동, 잦은 토글) | 제거하거나 거의 지각되지 않을 만큼 축소 |
| 가끔 (모달·드로어·토스트·설정) | 표준 애니메이션 허용 |
| 드묾/최초 1회 (온보딩·빈 상태·성공·축하) | 여기가 유일한 "연출 예산" |

- **키보드로 시작된 동작은 판단이 아니라 실격**이다 — 하루에 수백 번 반복되므로 애니메이션이 붙는 순간 느리고 끊긴 느낌이 된다.
- 모션의 정당한 목적은 다섯뿐: **피드백 · 공간 일관성 · 상태 표시 · 급변 완충 · 설명(마케팅·온보딩)**. 여기에 **연출(delight)** 은 "드묾" 등급에서만 추가된다.
- "멋있어서"는 목적이 아니다. 목적을 위 단어 중 하나로 부를 수 없으면 넣지 않는다.
- 사용자가 **읽거나 조작하려는 데이터**(대시보드 그래프·표·금액)는 장식으로 움직이지 않는다.

## 2. 이징 (easing)

**결정 순서** — 위에서부터 해당하는 첫 줄을 쓴다.

| 상황 | 이징 |
|---|---|
| 등장·퇴장(enter/exit) | `ease-out` |
| 화면 안에서 이동·변형(A→B) | `ease-in-out` |
| 호버·색 변화 | `ease` |
| 등속 반복(마퀴·진행바) | `linear` |
| 판단이 안 서면 | `ease-out` |

- **UI에 `ease-in`은 금지**다. 느리게 시작해서, 사용자가 가장 집중해 보는 첫 순간을 지연시킨다.
- 브라우저 내장 이징은 약하다. 강한 커스텀 커브를 토큰으로 둔다:

```css
--ease-out:    cubic-bezier(0.23, 1, 0.32, 1);     /* UI 등장·퇴장 기본 */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);    /* 화면 내 이동 */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);     /* iOS풍 드로어/시트 */
```

- 커브를 맨손으로 만들지 말고 easing.dev·easings.co 같은 도구에서 고른다.
- **되돌아가는 전환(열림↔닫힘)은 커브를 서로 미러링**한다(제어점을 뒤집은 역커브).

## 3. 지속시간 예산

| 요소 | 지속시간 |
|---|---|
| 버튼 눌림 피드백 | 100~160ms |
| 툴팁·작은 팝오버 | 125~200ms |
| 드롭다운·셀렉트 | 150~250ms |
| 모달·드로어 | 200~500ms |
| 마케팅·설명용 | 더 길어도 됨 |

- **UI 애니메이션은 300ms 미만**이 원칙이다. 180ms 드롭다운이 400ms짜리보다 반응이 빠르게 느껴진다.
- 300ms를 넘는 UI 모션에는 사유가 명시돼 있어야 한다. 없으면 발견 사항이다.
- **비대칭 타이밍**: 사용자가 "결정하는 구간"은 느리게, 시스템이 "응답하는 구간"은 빠르게. 길게 눌러 확인하는 동작(hold-to-confirm)은 누를 때 2s linear, 뗄 때 200ms ease-out처럼 갈라진다. 누름/뗌이 같은 시간이면 발견 사항이다.

## 4. 물리성과 원점

- **`scale(0)`에서 시작하지 않는다.** 현실에서 무(無)로부터 나타나는 것은 없다 → `scale(0.9~0.97)` + `opacity: 0`.
- **원점 인지(origin-aware)**: 팝오버·드롭다운·툴팁은 **트리거에서** 자라야 한다. `transform-origin: center`는 발견 사항이다.
  ```css
  .popover { transform-origin: var(--transform-origin); } /* Base UI 등이 제공 */
  ```
  **모달은 예외** — 뷰포트 중앙에 나타나므로 `center` 유지.
- **눌림 피드백**: `:active`에 `transform: scale(0.97)` + `transition: transform 160ms ease-out`. 범위는 0.95~0.98. 누를 수 있는 모든 요소에 적용된다.
- **공간 일관성**: 들어온 경로로 나간다. 오른쪽에서 들어온 패널은 오른쪽으로 사라진다. 아래로 사라지면 연결이 끊긴다.
- **translate의 %는 요소 자기 크기 기준**이다 — `translateY(100%)`는 자기 높이만큼 이동(하드코딩 px보다 안전).
- `scale()`은 자식(폰트·아이콘)까지 함께 키운다 — 눌림 피드백에선 이게 장점이다.

## 5. 인터럽트 가능성 (가장 자주 놓치는 축)

- **CSS transition은 진행 중 재타깃**된다. `@keyframes`는 처음부터 다시 시작한다.
- 따라서 **빠르게 반복 트리거되는 것**(토스트 추가, 토글, 드래그)에 keyframes를 쓰면 발견 사항이다.
- JS 없는 등장은 `@starting-style`:
  ```css
  .toast {
    opacity: 1; transform: translateY(0);
    transition: opacity 400ms ease, transform 400ms ease;
    @starting-style { opacity: 0; transform: translateY(100%); }
  }
  ```
  구형 대응은 `useEffect(() => setMounted(true), [])` + `data-mounted` 속성.
- **인터럽트 시 목표값이 아니라 현재 화면값(presentation value)에서 새 애니메이션을 시작**한다. 목표값에서 시작하면 눈에 보이는 점프가 생긴다.
- 제스처가 반대로 뒤집힐 때 **속도를 하드컷하지 않고 이어받는다**. 끊으면 "벽에 부딪힌" 느낌이 난다.
- 전환 중 **입력을 잠그지 않는다**. 닫히는 중인 모달을 다시 잡으면 손가락을 따라와야 한다.

## 6. 스프링과 제스처 물리

스프링은 지속시간이 없다 — 파라미터에 따라 정착한다. **드래그 모멘텀·상시 살아있는 요소·중간에 뒤집힐 수 있는 제스처**에 쓴다.

```js
// Apple식 (추론하기 쉬움) — 기본 권장
{ type: "spring", duration: 0.5, bounce: 0.2 }
// 전통 물리 파라미터 (제어폭 넓음)
{ type: "spring", mass: 1, stiffness: 100, damping: 10 }
```

**두 파라미터로 생각한다** — damping(오버슈트 정도)과 response(목표 도달 속도, 초). damping `1.0`은 임계감쇠(튐 없음), `<1.0`이면 진동한다.

| 상호작용 | damping | response |
|---|---|---|
| 이동·재배치 | 1.0 | 0.4 |
| 회전 | 0.8 | 0.4 |
| 드로어·시트 | 0.8 | 0.3 |

- 기본은 **damping 1.0(튐 없음)**. 바운스는 **제스처 자체가 모멘텀을 실었을 때만**(플릭·던지기·드래그 릴리스) 넣는다. 그냥 페이드인된 메뉴가 튀면 어색하다. 웹에서 `bounce`는 0.1~0.3.
- **1:1 추적**: Pointer Events + `setPointerCapture`, 잡은 지점의 오프셋을 존중한다(중앙으로 스냅하면 즉시 환상이 깨진다). 드래그 시작 후 추가 터치 포인트는 무시한다.
- **속도 핸드오프**: 손을 뗀 순간의 속도를 스프링 초기 속도로 넘긴다. 정규화가 필요한 API면
  `relativeVelocity = gestureVelocity / (target − current)`.
- **모멘텀 투영**: 뗀 지점이 아니라 **가려던 지점**으로 스냅한다.
  ```js
  function project(v /* px/s */, d = 0.998) { return (v / 1000) * d / (1 - d); }
  const target = nearestSnapPoint(current + project(releaseVelocity));
  ```
  교과서식 `v²/(2a)`가 아니라 위 지수감쇠 형태를 쓴다.
- **속도로 판정**: 닫을지 되돌릴지는 이동 거리 임계값이 아니라 **속도(부호·크기)**로 정한다. 스와이프 해제 임계는 대략 `|거리|/경과ms > 0.11`.
- **러버밴딩**: 경계에서 딱 멈추지 않고 갈수록 덜 따라온다.
  ```js
  function rubberband(overshoot, dim, c = 0.55) { return (overshoot * dim * c) / (dim + c * Math.abs(overshoot)); }
  ```
- 2D 이동은 **X·Y 스프링을 분리**한다(하나로 묶으면 속도가 다를 때 어긋난다).
- 마우스 추종 효과는 좌표를 직접 물리지 말고 `useSpring` 등으로 보간한다(직결은 관성이 없어 인공적이다). 장식 목적일 때만 쓴다.

## 7. 성능 (GPU)

- **`transform`과 `opacity`만 애니메이션한다** — 레이아웃·페인트를 건너뛰고 GPU에서 돈다.
- `width`/`height`/`margin`/`padding`/`top`/`left` 애니메이션과 `transition: all`은 발견 사항이다.
- **부모의 CSS 변수로 자식 transform을 구동하지 않는다** — 자식 전체 스타일 재계산이 돈다.
  ```js
  el.style.setProperty('--swipe-amount', `${d}px`); // 나쁨: 자식 전부 recalc
  el.style.transform = `translateY(${d}px)`;        // 좋음: 이 요소만
  ```
- **Framer Motion/Motion의 `x`/`y`/`scale` 축약형은 하드웨어 가속이 아니다**(rAF·메인 스레드). 부하 시 프레임이 떨어진다 → `transform: "translateX(100px)"` 문자열로.
- 부하 상황에선 CSS 애니메이션이 JS보다 낫다(메인 스레드 밖). JS 제어가 필요하면 **WAAPI**(`element.animate(...)`)가 CSS 성능 + 인터럽트 가능성을 함께 준다.
- 크로스페이드가 두 상태를 겹쳐 보여 지저분하면 전환 동안 `filter: blur(2px)` 정도를 섞어 하나의 변형으로 읽히게 한다(20px 미만 — 큰 블러는 특히 Safari에서 비싸다).

## 8. 스태거

- 그룹 등장은 항목 간 **30~80ms**. 더 길면 느리게 느껴진다.
- 스태거는 **장식**이다 — 재생되는 동안 상호작용을 막지 않는다.
- 한 화면이 통째로 동시에 튀어나오는데 스태거가 없다면(가끔 보는 화면일 때) 기회 후보다.

## 9. 모션 접근성

```css
@media (prefers-reduced-motion: reduce) {
  .el { transition: opacity 200ms ease; transform: none; } /* 이동은 빼고 불투명도는 남긴다 */
}
@media (hover: hover) and (pointer: fine) {
  .el:hover { transform: scale(1.05); } /* 터치에서 가짜 호버가 뜨는 걸 막는다 */
}
```

- **reduced motion은 "모션 0"이 아니라 "더 적고 더 순한 모션"**이다. 이해를 돕는 불투명도·색 전환은 남기고, 위치 이동·패럴랙스·탄성 오버슈트를 뺀다.
- React면 `useReducedMotion()`으로 값 자체를 갈아끼운다(`const closedX = reduce ? 0 : '-100%'`).
- 전체 화면을 덮는 배경 이동, 5초 주기쯤의 느린 반복 진동, 급격한 밝기 점프는 피한다.
- 호버 모션에 포인터 게이트가 없으면 발견 사항이다(모바일에서 탭 시 잔류 호버).

## 10. 응집(cohesion)과 판단 유보

- 모션은 **그 컴포넌트의 성격**과 맞아야 한다 — 소비자용 앱은 튀어도 되고, 업무 대시보드는 짧고 또렷해야 한다.
- 목록의 높이+불투명도 동시 전환처럼 **공식이 없는 구간**이 있다. 값을 단정하지 말고 "슬로모션으로 확인" 항목으로 넘긴다.
- 애매하면 **지우는 쪽**이 대체로 정답이다.

**확인 방법(코드만으로 판정 불가한 것)**
- 지속시간을 2~5배로 늘리거나 DevTools 애니메이션 패널로 슬로모션 재생 — 색 크로스페이드, 이징의 급정지, `transform-origin`, 동시 진행 속성 간 어긋남을 본다.
- 제스처(드로어·스와이프)는 **실기기**에서 확인한다(개발 서버 IP 접속 + 원격 디버깅).
- 다음 날 다시 본다 — 작업 중엔 안 보이던 어색함이 드러난다.

## 11. 용어 대조표 (요청을 정확한 단어로 옮길 때)

| 한국어 서술 | 용어 |
|---|---|
| 트리거 버튼에서 자라나듯 열림 | Origin-aware animation |
| 살짝 넘쳤다가 제자리 | Pop in / overshoot |
| 하나씩 차례로 등장 | Stagger |
| 같은 자리에서 A가 흐려지며 B가 나타남 | Crossfade |
| 모양이 다른 모양으로 변함 | Morph |
| 썸네일이 카드로 커지며 이동 | Shared element transition |
| 크기·위치가 바뀔 때 튀지 않고 이동 | Layout animation |
| 앞으로 갈 땐 왼쪽, 뒤로 갈 땐 오른쪽 | Direction-aware transition |
| 끝까지 당기면 저항하다 되돌아옴 | Rubber-banding |
| 던지면 관성으로 더 감 | Momentum / velocity handoff |
| 진행 중에 잡아 되돌릴 수 있음 | Interruptible animation |
| 누를 때 살짝 작아짐 | Press/tap feedback |
| 길게 누르면 차오름 | Hold to confirm |
| 가장자리를 깎아 들어가며 드러남 | Clip-path reveal |
| 선이 그려지듯 나타남 | Line drawing (SVG path) |
| 숫자가 굴러 올라감 | Number ticker (+ `tabular-nums` 필수) |
| 로딩 자리에 빛이 훑고 지나감 | Skeleton / shimmer |
| 스크롤에 진행이 묶임 | Scroll-driven animation |
| 배경이 다른 속도로 움직임 | Parallax |
| 끊겨 보이는 버벅임 | Jank / dropped frame |
| 레이아웃 속성 애니메이션으로 생기는 재계산 | Layout thrashing |

> 표에 없는 효과는 가장 가까운 용어를 대고 "근사치"라고 밝힌다. 없는 용어를 지어내지 않는다.
